## Поэкранные потребители

- **Журнал / запись / подтверждение / повтор:** общий `recordMiniCard()`; отдельная часть браузерных тестов проверяет Q, fixed head/foot и scrolling-center.
- **Контакты / рабочее пространство / история:** общая EntityCard и общий MiniCard; история и детальная Q-карта теперь используют один адаптер данных `contactRecordMiniCard()`. Действия «открыть»/«повторить» независимы. Все услуги остаются в прокручиваемом центре.
- **Интеграции календаря:** `providerMiniCard()` — только адаптер данных к `miniCard()`, не альтернативный UI; общий 290×200 из `staging`.
- **Профиль, личные данные, программы, депозит, личный счёт:** `entityVisualCard()`, общий Q и list-entry; Core/API остаётся источником данных. Разные бизнес-разделы не равны CSS-дубликатам.
- **Заметки / события / документы / уведомления / настройки / авторизация:** существующие Z/Q/X/S/technical и Shared Controls, без создания нового слоя CSS. Обновлён `openNotice()` для реального technical.
- **Старый чек истории:** отдельный генератор `readOnlyReceipt` и CSS больше не используются и удаляются в рамках закрывающей очистки. Оплата/задолженность сохраняются как данные карточки внутри прокручиваемой зоны.

## Исправления в этом наборе (до запуска новых CI)

1. Проброшены интерактивность, атрибуты открытия и доступность клавиатурного открытия Record MiniCard. Повтор имеет независимое действие без двойного открытия Q.
2. История и подробности записи используют единый вариант MiniCard с оплатой/долгом как данными, без второго `readOnlyReceipt`; убран обрезающий `.slice(0, 4)`.
3. `recordMiniCard` допускает переданные `details` и для детального просмотра, без изменения Journal при отсутствии этих данных.
4. `openNotice` соблюдает технический тип уведомления, при обычном типе оставляет информационный S.
5. Удалены неиспользуемые `ui/receipt/index.js`, `ui/receipt/receipt.css` и их HTML-включение.
6. В CI добавлены проверки потребителей мини-карты/технических уведомлений и запрет возврата старого чека.
7. Production Availability CI ищет фактический JS по хешированному пути из HTML, а не старый `/user/main.js`; проверяет HTTP/TLS, MIME, непустой файл и синтаксис JS.

## Границы проверки и критерий закрытия

- **Статика / CI:** заново должны пройти Repository, Shared UI, Profile, Record, Chromium smoke и Staging Smoke на конкретном новом SHA. При провале статус — «в проверке», не «закрыто».
- **Runtime / визуал:** ещё требуется посмотреть реальный staging в iPhone: History (много услуг, открытие, повтор), Calendar integrations, Q/technical, карты/поля/селекторы/списки и клавиатура. Не считать визуально подтверждённым по source code или CI.
- **API:** staging preview обращается к производственному Core API. Реальные записи/платежи/согласия не тестировать на живых данных без согласованного тестового аккаунта и сценария. Core и его БД не изменялись.
- **Граница релиза:** `main` не изменять до отдельного одобрения владельца, зелёного PR Gate и устройства. После утверждённого выпуска `user/main` становится новой эталонной версией; Professional приводится к ней отдельной задачей.
